### 根因修正（回归“只压缩低阶、不砍原生高阶”原意）
1. **移除全局密度削减（`RoamingDensityScale = 1.0`）**：`CoopBalanceManager` 不再把 `ZXMapTheme.InfectedFactor` 砍到 `0.85 / 0.80`，全图近/中/外圈均保留 `1.0×` 原版原生刷怪基数，确保外圈原生 T3 特感不被事先削弱。
2. **纯低/中阶升格压缩代替全局降密度**：在完整保留原生 T3 的前提下，把外圈冗余低阶按 BTK 权重（`1.0` / `1.6` → `Chubby=5.0 / Venom=3.0 / Harpy=3.0`）压缩升格，将全图总实体数自然收口到流畅上限以内，同时让边界区局部高阶密度直接回到执政官 / 原版同级高压水准。

## 2. 后期主力（狙击手）BTK 与僵尸输出威胁模型

### 2.1 野图推进场景（流动狙击手群，无城墙/无电塔 AOE）

| 僵尸类型 | 狙击手 BTK | 输出模式与威胁特征 | 等效 BTK 威胁权重 |
|---|---:|---|---:|
| **Weak (T1)** | `1` 枪（过量伤害浪费） | 慢速近战，8 格射程外即被点死，对成型狙击群几乎无输出 | **`1.0`** |
| **Med / Strong (T2)** | `1~2` 枪（均约 `1.3~1.6` 枪） | 跑尸/高移速/中高血量，成群可消耗前排或迫使走 A | **`1.6`**（输入预算） |
| **Chubby (胖子 T3)** | **`5~6` 枪** | 慢速纯肉盾，核心作用是吸收大量狙击手开火轮次 | **`5.0`** |
| **Venom (毒液 T3)** | **`2` 枪** | 远程 AOE 酸液吐息，可隔着肉盾融化扎堆狙击手 | **`3.0`** |
| **Harpy (女妖 T3)** | **`2` 枪** | 极高移速 + 翻墙 + 高频近战，容错率最低 | **`3.0`** |

**核心推导**：
- **若统一用 `4:1` 或 `9:1` 换算女妖/毒液**：女妖/毒液仅需 2 枪，按 `4:1` 甚至 `9:1` 换算会直接砍半狙击手总开火次数，导致 `SwarmHunter`/`Caustic` 图比原版更好推；
- **若统一用低比例换算胖子**：胖子需 5~6 枪，换多之后极易拖慢推进节奏变成刮痧。
- 因此采用 **BTK 权重预算池**：抽调外圈 `60% T1`（每只 `+1.0`）与 `45% T2`（每只 `+1.6`）进入预算池，生成 `Chubby` 扣除 `5.0`、生成 `Venom/Harpy` 扣除 `3.0`（在 `num49 >= 3` 且预算充足时按 `1/3` 概率升级双怪格并双倍扣费）。

### 2.2 分圈升格与中低阶回填（兼顾高阶密度与总量）

1. **近圈（`d_min < minMed`）**：`100%` 保留原版动态噪声安全圈与刷怪结果。
2. **中圈（`minMed <= d_min < effOuterStart`）**：抽取 `40%` `Weak(T1)` 按 **`2.5 : 1`** 升格为 `Strong`（70%）/`Medium`（30%），补回中圈扩图阻力。
3. **外圈（`d_min >= effOuterStart`，聚集模式取 `minPowerful`，分离模式内收 `10` 格对齐外圈面积）**：
   - 在 `RoamingDensityScale = 1.0` 原生基数上，抽调外圈 **`70%` `T1`（每只 `+1.0`）** 与 **`50%` `T2`（每只 `+1.6`）** 投入 BTK 预算池，在 `num49 >= 2` 且预算充足时按 `1/2` 概率生成双怪格，原生 T3 全额保留，并在 `d_min >= 85` 按每 `28` 个 T3 凝聚 `1` 只外围巨人（受 `maxCondensedGiants` 上限约束）。
4. **总量保底回填（`d_min >= minWeak`）**：当大比例压缩导致全图总僵尸数低于 `min(25,000, round(升格前原生总数 × 0.85))` 时，在合格空噪声格回填 `Weak2` / `Runners1` / `Medium1`，保证 30Hz 流畅度的同时保留充足低阶混编阵型。

## 4. `PlayableArea` 旋转菱形坐标修正与最终实测结果（VO 900%）

### 4.1 坐标空间 Bug 修复
- **问题**：`DXLevel.PlayableArea` 位于等轴测屏幕坐标系（Scene Coordinates），对应世界格子坐标中的 **45° 旋转菱形**（面积约为场景边长平方的 `√2` 倍）。先前 `MultiBaseMapGenerator.RewriteZombieRingsAndBosses` 直接用 `playable.Left..Right / playable.Top..Bottom` 作为世界格子 `(x, y)` 的截断方框，导致菱形东西南北 4 个外圈大三角区（约 `35.8%` 的可玩面积）被清零，同时方框四角凸出菱形外误刷了 ~2,000+ 只无效边界 T3。
- **修复**：新增 `IsCellInPlayableArea(x, y, playable, gN)` 直接判定 `playable.Contains(DXWorldGrid.ScenePointFromWorldCell(x, y, gN))`，并为 `IsWithinSafePlayable` 显式传入 `gN`，避免切换地图尺寸时沿用旧 `DXWorldGrid.NCellsDiv2F`。
