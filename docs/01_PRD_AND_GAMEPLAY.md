# 01 — 产品需求与玩法交互设计 (PRD & Gameplay Specification)

## 1. 项目愿景与核心目标

为《亿万僵尸》（They Are Billions）打造原汁原味、零服务器门槛的 **2~3 人 Steam P2P 合作联机 Mod**：
- **无需公网 IP 或自建专用服务器**：依托 Steamworks P2P（SteamLobby + SteamNetworking SDR 中继），支持好友直接创建房间、Shift+Tab 邀请加入。
- **双联机玩法支持**：
  1. **模式一（优先核心交付）：执政官模式（Archon Mode / 共控一族）** —— 2-3 名玩家共同执掌同一个人类帝国殖民地，分工负责运营建造、多线清图、暴兵与尸潮防守。
  2. **模式二（第二阶段拓展）：独立基地模式（Independent Bases Mode / 各自为战合作守图）** —— 每名玩家拥有独立的指挥中心（Command Center）、独立经济资源池与单位控制权，协同防守同一张地图。

## 2. 模式一：执政官模式（Archon Mode）详细交互设计

在执政官模式下，游戏底层仍然只有 1 个人类阵营（`ZXTeamType.Player`），但允许 2~3 名玩家以**完全独立的视角与交互上下文**同时操作。

### 2.1 玩家身份与色彩标识
房间内支持最多 3 名玩家，固定分配高辨识度主题色：
- **Player 1 (Host / 房主)**：皇家蓝（`Color.DodgerBlue` / `#1E90FF`）
- **Player 2 (Client 1)**：翡翠绿（`Color.SpringGreen` / `#00FF7F`）
- **Player 3 (Client 2)**：琥珀橙（`Color.Orange` / `#FFA500`）

### 2.2 本地独立状态 vs 全局共享状态

| 维度 | 状态归属 | 交互表现说明 |
| :--- | :--- | :--- |
| **摄像机视野 (Camera)** | **本地独立** | 每名玩家自由平移（WASD/鼠标滚屏）、缩放（滚轮）各自的屏幕，互不拉扯视角。 |
| **单位/建筑框选 (Selection)** | **本地独立** | 玩家 A 框选左路游侠，玩家 B 框选家里兵营或右路狙击手，各自下方属性栏与右下方命令面板显示自己选中的对象，**绝不互相顶掉选中状态**。 |
| **编队快捷键 (Ctrl+1~9)** | **本地独立** | 每名玩家的编队保存在各自客户端本地，按数字键仅选中/跳转自己的编队。 |
| **建筑建造预览 (Build Ghost)** | **本地独立** | 玩家 A 处于“拉电塔/拉木墙”的网格预览模式时，不影响玩家 B 的鼠标状态；直到玩家 A 左键点击落地的瞬间，才在全局生成建造地基。 |
| **资源与电力/食物池** | **全局共享** | 金币、木材、石头、铁矿、石油、电力、食物、工人数量全员共享，任何人的建造/训练都会实时扣减公共资源池。 |
| **单位与建筑控制权** | **全局共享** | 任何人都可以选中并下达移动/攻击/技能指令给任何人类单位或建筑（后下达的指令按逻辑帧顺序覆盖该单位的前序指令，与《星际争霸2》执政官模式一致）。 |
| **战争迷雾 (Fog of War)** | **全局共享** | 共享全部人类建筑与单位的视野层（`LayerFog`）。 |

### 2.3 时间控制（空格暂停与游戏速度）
《亿万僵尸》是重度依赖“暂停建房、暂停拉兵”的游戏，联机下的暂停体验至关重要：
1. **暂停触发**：
   - 默认策略（**自由协作模式**）：任意玩家按下 `Space`（空格）或点击右上角暂停按钮，均可通过网络指令在下一个同步 Tick 将全员游戏置为 `Paused = true` 或恢复运行。
   - 屏幕顶部中央（复用游戏原生提示条 `ZXSystemGameLevel.#=zhWLC3K8=`）立即向全员显示提示：`"[玩家名] 暂停了游戏"` 或 `"[玩家名] 恢复了游戏"`。
   - 可选房间设置（**防误触就绪模式**）：暂停可由任意人立即触发，但恢复运行需要房主操作，或全员按空格确认就绪。
2. **暂停期间的操作**：
   - 与原版单机完全一致！暂停期间所有玩家依然可以自由平移视角、框选单位、下达移动/攻击指令、放置建筑、点击招募、拆除建筑。
   - **技术要点**：暂停期间 `GameTime` 虽然不推进，但我们的 `LockstepManager` 依然以 30Hz 维持“网络控制帧（Control Tick）”心跳，确保暂停期间队友放下的建筑地基、下达的移动路径能**实时（<100ms）**在所有人的屏幕上显示出来！

### 2.4 市长选举（Mayor Selection）同步机制
当殖民地人口达到阈值（30 / 100 / 200 / 600 / 1200）触发市长选举弹窗（`ZXGame.#=zcITiOSD6YNmD`）时：
1. 由于随机数种子已同步，所有玩家屏幕上同时弹出完全相同的两位候选市长（一男一女）。
2. **决策模式（支持房间切换，默认采用“房主拍板 + 队友意向高亮”）**：
   - **客机点击“选择”按钮时**：不直接关闭窗口，而是在两位玩家屏幕上将该客机选中的市长卡片外框高亮为其代表色（例如显示 `"[玩家2 推荐]"` 标记）。
   - **房主点击“选择”按钮时**（或当房间设为“先点生效”模式时任意人点击）：发送 `SelectMayorCommand(int slotIndex)`，全员同步应用该市长加成、关闭弹窗并在左侧通知栏生成市长图标。

### 2.5 盟友态势感知（Co-op UX 增强）
为了让 2-3 人配合丝滑、避免“两个人同时在同一个地方造猎人小屋”或“不知道队友在看哪”：
1. **小地图队友视野框**：
   - 在右下角小地图（`OMiniMap`）上，除了原有的白色本地视野框外，实时绘制队友代表色（绿/橙色）的视野矩形框。
2. **大地图队友光标与建造预览提示**：
   - 在世界地面上绘制队友的彩色鼠标指针及玩家名标签。
   - （进阶）当队友正处于 `IsInBuildingMode` 准备放置建筑时，在地面显示半透明的队友色彩占位框，防止两人同时往同一块地皮拍建筑。
3. **小地图与地面信号打点（ Tactical Ping）**：
   - 按住 `Alt + 左键`（或中键点击地面/小地图），向全员发送 `PingCommand(Point cell, int playerId)`。
   - 直接调用游戏原生小地图雷达波纹动画 `OMiniMap.#=zvr$ku1Q=` 并配合提示音，在地面与小地图同时闪烁队友颜色的信号圈。

## 3. 大厅、开局与断线重连流程（Lobby & Session Flow）

### 3.1 主菜单入口与 Steam 房间大厅
1. 在游戏主菜单（`NEW GAME` / `CONTINUE` 所在列表）注入 **`[ CO-OP MULTIPLAYER ]`** 按钮。
2. 点击后打开原生暗黑蒸汽朋克风格的 `ZXWindow` 联机大厅窗口：
   - **创建房间（Host Lobby）**：调用 `SteamMatchmaking.CreateLobby(k_ELobbyTypeFriendsOnly, 3)`。
   - **邀请好友（Invite Friends）**：调用 `SteamFriends.ActivateGameOverlayInviteDialog(lobbySteamId)` 直接弹出 Steam 好友邀请列表；同时支持好友在 Steam 列表右键“加入游戏”。
   - **本地环回测试按钮（Local Loopback）**：供开发与 AI Agent 单机多开直接通过 `127.0.0.1:27099` 握手连接。

### 3.2 零地图生成差异的“内存存档流直传”开局流程
为了彻底规避随机地图生成器（`ZXRandomLevelParams`）跨机器差异，并同时支持“新建游戏联机”和“读取已有单机存档转联机”：
1. 房主在大厅内点击 **“开始新生存游戏”** 或 **“加载已有存档”**。
2. 客机界面显示 **“房主正在配置并生成世界，请稍候...”**。
3. 房主正常完成地图选关并加载进入游戏场景（此时游戏自动锁定在初始暂停状态）。
4. Mod 自动在房主端调用原生存档序列化生成临时 `.zxsav` 快照（约 1~3 MB），通过 Steam P2P Reliable 通道分片流式发送给所有客机（显示传输进度条，通常 1~3 秒完成）。
5. 客机接收完毕后写入临时目录，调用原生读档流程 `ZXGame.#=z9IpK6P4YlW8GIY7olg==` 直接进入完全一致的地图状态。
6. 全员加载完成并校验初始 `StateHash` 一致后，弹出 `“全员连接就绪！按空格键开始游戏”`。

### 3.3 状态校验与一键热同步（Auto-Resync）
- 游戏过程中每 60 逻辑帧（2秒）后台自动比对房主与客机的 `StateHash`（包含金木石铁油、电力食物、单位总数、建筑总数、所有实体坐标与生命值校验和）。
- 若检测到任何微小的 Desync（或有玩家中途断线重连）：
  - 房主自动触发（或点击 HUD 上的 `Resync` 按钮）一次后台快照广播，客机在 2~3 秒内无缝重载最新快照，**绝不因为一次偶发的算力偏差而报废整局几小时的存档**。

## 4. 模式二（第二阶段架构预留）：独立基地模式设计概要

在执政官模式稳定后，架构无缝扩展支持“每家一个独立基地”：
1. **多基地生成**：房主开局生成地图时，在距离主基地一定安全距离的对称/半对称可用空地上，额外生成第 2、3 座 `CommandCenter` 及初始帐篷/游侠。
2. **Mod 层独立账本（Virtual Faction Ledger）**：
   - 为每个建筑和单位通过附加组件（或 `Dictionary<ulong, byte> EntityOwnerMap`）标记所属玩家 ID（`OwnerId = 1, 2, 3`）。
   - 维护三套独立的 `PlayerResourcePool`（金、木、石、铁、油、工人、食物、电力）。
   - 本地 UI 顶栏 Hook `OResourcesLabel`，仅渲染当前玩家自己的资源池；下达建造/训练命令时校验并扣减命令发起者的资源池。
3. **操作权限隔离**：
   - 在獨立基地模式下，玩家默认只能框选、控制、拆除 `OwnerId == LocalPlayerId` 的单位与建筑（可通过房间设置开启“允许盟友代管部队”或“允许资源转账贸易”）。
   - 尸潮分配：利用 `ZXLevelEvent` 生成尸潮时，将尸潮单位按比例分流，分别以 2-3 座指挥中心作为进攻终点（`DefaultCellInfectedDestiny`）。
